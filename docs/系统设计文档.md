## 3. 平台管理系统（新增/删除 + Web端登录）

### 3.1 设计思路

用户可以在 Web 工具中管理平台列表：
- **新增平台**: 触发后端打开该平台登录页的浏览器 → 通过 WebSocket 将浏览器截屏实时推送到前端 → 用户在前端看到登录页 → 后端浏览器是带头的（有 GUI），用户在自己的桌面直接操作浏览器窗口完成登录 → 登录成功后 cookie 自动保存 → 平台添加完成
- **删除平台**: 移除 cookie 文件 + 删除数据库记录

### 3.2 登录流程（Web端触发 + 本地桌面操作）

```
用户点击「+ 新增平台」→ 选择平台（如下拉选「CSDN」）
        │
        ▼
后端: 从 BrowserPool 获取一个 Chromium 实例（headed 模式）
      → 打开 CSDN 登录页 https://passport.csdn.net/login
        │
        ▼
后端: WebSocket 向前端推送浏览器截屏（每秒1帧，降低带宽）
      同时在用户本地桌面弹出一个 Chrome 窗口（用户可直接操作）
        │
        ▼
用户: 在本地 Chrome 窗口中扫码/输密码完成登录
      （注意：这是用户本机，浏览器窗口自然可见）
        │
        ▼
后端: 轮询检测登录成功（URL变化 / cookie出现 / 页面元素变化）
      → 保存 cookie 到 ./browser-states/CSDN.json
      → 在 user_platform 表插入记录
      → WebSocket 通知前端 "登录成功"
        │
        ▼
前端: 平台列表刷新，CSDN 出现在 Tab 栏中，状态绿点
```

### 3.3 为什么能在Web端完成

因为这是**本地开发/部署**的工具，Spring Boot 运行在用户本机。Playwright 打开的 Chrome 窗口也出现在用户本机的桌面上。用户可以**直接**在弹出来的 Chrome 窗口里操作。前端只负责触发和查看状态。

```
用户电脑 (localhost)
┌──────────────────────────────────────────┐
│  浏览器 (Vue3 前端)        桌面           │
│  ┌─────────────────┐   ┌──────────────┐  │
│  │ 平台管理页面     │   │ Chrome 窗口   │  │
│  │                 │   │ (Playwright   │  │
│  │ [新增平台] →    │   │  打开的登录页) │  │
│  │ 状态: 等待登录...│   │              │  │
│  │ ✅ 登录成功     │   │ 用户扫码登录  │  │
```

## 4. 视频大小：按平台限制校验

### 4.1 各平台视频限制（真实数据）

| 平台 | 视频上传方式 | 大小限制 | 时长限制 | 格式 |
|------|------------|----------|----------|------|
| 微信公众号 | 素材库上传 | ≤1GB | ≤30分钟 | mp4 |
| 知乎 | 不支持视频（图文） | N/A | N/A | N/A |
| B站 | 网页端上传 | ≤8GB | ≤10小时 | mp4/flv/avi |
| 小红书 | 不支持视频（图文） | N/A | N/A | N/A |
| 头条号 | 素材库上传 | ≤4GB | ≤60分钟 | mp4 |
| CSDN (自定义) | 取决于平台 | 用户配置 | 用户配置 | 用户配置 |

### 4.2 校验流程

```
用户上传视频
    │
    ▼
前端: 读取视频元信息 (大小, 时长)
    │
    ▼
后端: 查询各平台视频规则，返回限制信息
  GET /api/platform/video-limits
  → {
       "WECHAT":  { "maxSizeMB": 1024, "maxDurationSec": 1800, "formats": ["mp4"] },
       "ZHIHU":   { "supported": false, "reason": "知乎图文不支持视频" },
       "BILIBILI":{ "maxSizeMB": 8192, "maxDurationSec": 36000, "formats": ["mp4","flv","avi"] },
       "XHS":     { "supported": false, "reason": "小红书图文不支持视频" },
       "TOUTIAO": { "maxSizeMB": 4096, "maxDurationSec": 3600, "formats": ["mp4"] }
     }
    │
    ▼
前端: 在预览卡片中针对每个平台显示校验结果:
  知乎 Tab:    ⚠ 该平台不支持视频，已自动移除视频内容
  B站 Tab:     ✅ 视频 200MB, 8分钟 — 符合限制
  小红书 Tab:  ⚠ 该平台不支持视频，已自动移除视频内容

    │
    ▼

```

### 4.3 跨平台视频处理策略

```java
// PlatformService.java
public Map<String, VideoValidation> validateVideoForAllPlatforms(VideoInfo video) {
    Map<String, VideoValidation> results = new HashMap<>();
    for (PlatformAdapter adapter : adapterRegistry.getAllAdapters()) {
        PlatformFormatRules rules = adapter.getFormatRules();
        if (!rules.isSupportVideo()) {
            results.put(adapter.getPlatformCode(),
                VideoValidation.unsupported("该平台不支持视频"));
        } else if (video.getSizeMB() > rules.getMaxVideoSizeMB()) {
            results.put(adapter.getPlatformCode(),
                VideoValidation.exceeded(
                    video.getSizeMB(), rules.getMaxVideoSizeMB(),
                    rules.getMaxVideoDurationSec()));
        } else {
            results.put(adapter.getPlatformCode(), VideoValidation.ok());
        }
    }
    return results;
}
```

## 5. 预览卡片：轻量 Tiptap 编辑器（核心变化）

### 5.1 预览卡片不止是文字编辑

用户要求：预览卡片上可以**改文字、调样式（加粗/斜体/标题）、移动图片位置、新增图片**。这需要一个完整的轻量编辑器，不只是 contenteditable。

**方案: 每个预览卡片嵌入一个轻量 Tiptap 实例。**

```
主 Tiptap 编辑器（左侧）          预览卡片内 Tiptap 实例（右侧）
┌──────────────────────┐    ┌──────────────────────────┐
│ 完整工具栏            │    │ 轻量工具栏:              │
│ B I U H1 H2 H3       │    │ B I U H2 H3 图片 链接    │
│ 图片 视频 引用 列表   │    │ (仅常用按钮)             │
│ 代码块 分割线         │    │                          │
│                      │    │ [适配后的内容]            │
│ [用户写的原始内容]    │    │ 用户可直接编辑、         │
│                      │    │ 拖拽图片调整位置、       │
│                      │    │ 新增图片、修改样式       │
└──────────────────────┘    └──────────────────────────┘
```

### 5.2 预览卡片 Tiptap 配置

```typescript
// composables/usePreviewEditor.ts
import { useEditor } from '@tiptap/vue-3'
import StarterKit from '@tiptap/starter-kit'
import Image from '@tiptap/extension-image'
import ImageResize from 'tiptap-extension-resize-image'  // 图片拖拽调整大小

export function usePreviewEditor(initialHtml: string, platformCode: string) {
  const editor = useEditor({
    content: initialHtml,
    extensions: [
      StarterKit.configure({
        // 只开启基础功能
        bold: true,
        italic: true,
        heading: { levels: [2, 3] },  // 平台通常不支持 h1
        bulletList: true,
        orderedList: true,
        blockquote: true,
      }),
      Image.configure({ allowBase64: false }),
      ImageResize,  // 用户可拖拽调整图片大小
      // 根据平台禁用不支持的功能
      ...getPlatformExtensions(platformCode),
    ],
    editable: true,
    onUpdate: ({ editor }) => {
      // 实时保存到 content_platform_version 表
      savePlatformVersion(platformCode, editor.getHTML())
    }
  })

  return editor
}
```

## 6. 模板系统（核心交互）

### 6.1 模板是什么

**模板 = 用户收藏/自建的风格参考样本。** AI 读取模板中定义的风格特征，按这个风格改写用户的内容，结果展示在预览卡片中。

模板有两种来源：
- **系统预置 5 套** — 内置的开箱即用模板
- **用户自建模板** — 用户把自己喜欢的文章/文案保存为模板，后续可重复使用

### 6.2 用户创建自己的模板（两种方式）

**方式一：粘贴参考文本**

```
在模板管理面板点击 [+ 新建模板]
        │
        ▼
填写模板名称 + 描述 + 粘贴参考文本
        │
        ▼
点 [分析文本样本] → DeepSeek 自动提取风格特征
        │
        ▼
保存模板
```

**方式二：上传参考图片（推荐）**

用户在小红书/公众号看到一篇排版精美的文章 → 截图保存 → 上传截图作为模板参考：

```
用户上传一张参考图片（如小红书爆款笔记截图）
        │
        ▼
POST /api/templates/analyze-image
  → DeepSeek Vision 分析图片:
     "这是一张小红书笔记截图。
      视觉特征:
      - 封面图占据顶部1/3，带大号emoji标题
      - 正文每段2-3行，段间用emoji分隔
      - 底部有#话题标签，标签用彩色底
      文字风格:
      - 语气: 闺蜜聊天式，亲切口语
      - emoji密度: 每段3-5个，🔥✨💯频繁出现
      - 句式: 短句为主，大量感叹号
      - 特征词: '绝了'、'救命'、'谁懂啊'、'姐妹们'
      - 结尾: 引导互动"姐妹们都给我冲!!!"
      推荐模板名: 小红书爆款种草风"
        │
        ▼

用户确认/微调 → 保存
```

```
用户在左侧编辑器写好原始内容
        │
        ▼

        │

{
  "contentId": 123,              // 原始内容

  1. 加载模板的 systemPrompt ("你是一个小红书爆款测评博主...")

        │
        ▼
前端:
  小红书预览卡片的 Tiptap 编辑器自动更新为改写后内容
  用户可在预览编辑器中继续微调
```

## 9. 格式适配保证机制

### 四层保证

```
第一层: 后端转换规则
  Tiptap JSON → 按平台规则过滤/转换 HTML

第二层: 预览编辑器（轻量 Tiptap）
  用户在预览中看到真实渲染效果
  → 不符合平台规则的内容在编辑器中就能发现

第三层: 平台规则校验提示
  预览卡片底部实时显示: 字数、图片比例、视频是否支持

第四层: 平台真实编辑器（最终保证）
  Playwright 将 HTML 填入平台原生编辑器
  → 平台自己的编辑器校验 + 渲染
  → 格式错误会被平台拒绝
```

## 10. 发布稳定性保障

### 10.1 可能出问题的地方

| 环节 | 风险 | 影响 |
|------|------|------|
| 登录态 | Cookie 过期、被平台踢出 | 发布失败 |
| 页面加载 | 编辑器页面加载慢/白屏 | 无法填入内容 |
| DOM变化 | 平台改版选择器失效 | 找不到标题框/发布按钮 |
| 内容填入 | HTML过大导致浏览器卡顿 | 填入不完整 |
| 弹窗干扰 | 平台弹出公告/验证码/新手引导 | 阻塞发布按钮 |
| 发布按钮 | 按钮disabled、被遮挡、不在视口 | 点击无效 |
| 网络波动 | 请求超时、连接断开 | 未知状态 |
| 浏览器崩溃 | Chromium 进程挂掉 | 全部中断 |
| 并发争抢 | 多平台同时发布抢占BrowserPool | 排队超时 |
| 平台限流 | 发布太频繁被平台临时限制 | 发布被拒 |

### 10.2 五层稳定性策略

**第1层: 发布前预检 (Pre-flight Check)**

在真正发布之前，先做快速检查，不通过则直接拒绝，不给用户假期望：

```java
// PublishPreflightChecker.java
public PreflightResult check(String platformCode) {
    // 1. 登录态有效性
    if (!loginStateManager.isStateValid(platformCode)) {
        return PreflightResult.fail("登录态已过期，请重新登录");
    }
    // 2. 平台页面可达性
    try (PlaywrightSession session = browserPool.acquire()) {
        loginStateManager.loadState(session, platformCode);
        Response resp = session.getPage().navigate(getEditorUrl());
        if (resp.status() >= 400) {
            return PreflightResult.fail("平台编辑器页面不可达: HTTP " + resp.status());
        }
    }
    // 3. 关键DOM元素存在
    if (!session.getPage().locator(getTitleSelector()).isVisible()) {
        return PreflightResult.fail("页面结构可能已变更，请检查平台选择器配置");
    }
    return PreflightResult.ok();
}
```

**第2层: 操作级重试 + 智能等待**

每个 Playwright 操作都有独立的超时和重试：

```
填标题:   waitForSelector(timeout=10s) → fill() → 失败则重试2次
填内容:   waitForSelector(timeout=15s) → evaluate() → 失败则截图
点发布:   waitForSelector(timeout=15s) → scrollIntoView() → click()
          → 失败则尝试 forceClick() → 再失败则截屏报错
等结果:   waitForSelector(successIndicator, timeout=30s)
          → 超时则截图当前页面状态 → 标记为"状态未知"
```

```java
// 通用重试包装
private <T> T retryOnFailure(int maxRetries, String stepName,
                              PlatformCode code, Supplier<T> action) {
    for (int i = 0; i < maxRetries; i++) {
        try {
            return action.get();
        } catch (PlaywrightException e) {
            if (i == maxRetries - 1) {
                // 最后一次失败: 截图 + 记录详细错误
                String screenshot = session.screenshot();
                log.error("{} 重试{}次后仍失败: {}", stepName, maxRetries, e.getMessage());
                throw new PublishException(code, stepName, e.getMessage(), screenshot);
            }
            log.warn("{} 第{}次失败, 1秒后重试...", stepName, i + 1);
            sleep(1000);
        }
    }
}
```

**第4层: 多步骤截图审计**

每个发布任务的关键步骤自动截图，出问题时能回溯：

```
发布任务截图链:
  step1_before_fill.png   → 进入编辑器后、填入前
  step2_after_fill.png    → 填入内容后
  step3_after_publish.png → 点击发布后
  step4_result.png        → 最终结果页

```

**第5层: 发布队列 + 隔离**

```
发布请求 → PublishQueue（按平台隔离）
  ├── 公众号队列: [任务1] → 串行执行
  ├── 知乎队列:   [任务2] → 串行执行
  ├── B站队列:    [任务3] → 串行执行
  └── ...         (同一平台串行，不同平台可并行)

每个任务:
  - 独立 BrowserContext (cookie隔离)
  - 独立超时计时器 (最长3分钟)
  - 超时自动中断 → 标记FAILED → 释放浏览器回池
```

```java
// PublishQueueManager.java
@Component
public class PublishQueueManager {
    // 每个平台一个单线程执行器
    private final Map<String, ExecutorService> queues = new ConcurrentHashMap<>();

    public CompletableFuture<PublishResult> submit(String platformCode,
                                                     Supplier<PublishResult> task) {
        ExecutorService queue = queues.computeIfAbsent(platformCode,
            k -> Executors.newSingleThreadExecutor());
        return CompletableFuture.supplyAsync(task, queue)
            .orTimeout(3, TimeUnit.MINUTES)        // 3分钟超时
            .exceptionally(ex -> PublishResult.fail(platformCode,
                ex instanceof TimeoutException ? "发布超时" : ex.getMessage()));
    }
}
```

### 10.4 发布状态机

```
PENDING → PREFLIGHT → FILLING → PUBLISHING → CONFIRMING → SUCCESS
                    ↓           ↓            ↓            ↓
                  FAILED      FAILED       FAILED       FAILED
                    ↓           ↓            ↓            ↓
               [可重试]    [可重试]     [可重试]     [可重试]
```

每个状态变化都通过 SSE 推送给前端，用户始终知道发布进行到哪一步。失败时返回具体步骤名称 + 截图，用户可以判断是否重试。

## 11. 内容撤回功能

### 11.1 撤回原理

已发布的文章通过 Playwright 反向操作撤回：打开平台内容管理页 → 定位到已发布的文章 → 执行删除/下架操作。

```
用户点击「撤回」
      │
      ▼
后端: 查询 publish_log 获取已发布文章的 platform_url
      ↓
从 BrowserPool 获取浏览器 → 加载平台登录态
      ↓
导航到平台内容管理页（如 mp.weixin.qq.com 的素材管理）
      ↓
定位到目标文章（通过标题匹配 / URL匹配）
      ↓
点击「删除」→ 确认弹窗 → 截图留存
      ↓
更新 publish_log.status = RETRACTED
      ↓
SSE 通知前端撤回成功
```

### 11.2 各平台撤回入口

| 平台 | 内容管理页 | 定位方式 | 删除方式 |
|------|-----------|----------|----------|
| 公众号 | `mp.weixin.qq.com` 素材管理 | 标题文字匹配 | 悬停→删除→确认 |
| 知乎 | `zhuanlan.zhihu.com` 文章管理 | 标题匹配 | 更多→删除→确认 |
| B站 | `member.bilibili.com` 专栏管理 | 标题匹配 | 删除按钮→确认 |
| 小红书 | `creator.xiaohongshu.com` 笔记管理 | 标题匹配 | 更多→删除→确认 |
| 头条 | `mp.toutiao.com` 内容管理 | 标题匹配 | 删除→确认 |

### 11.3 适配器新增接口

```java
// PlatformAdapter.java 新增方法
public interface PlatformAdapter {
    // ... 已有方法 ...

    /** 撤回已发布的内容 */
    RetractResult retract(String platformUrl, String title);

    /** 是否支持撤回（所有Playwright平台都支持） */
    default boolean supportRetract() { return true; }

```

```java
// AbstractPlatformAdapter.java 新增模板方法
public final RetractResult retract(String platformUrl, String title) {
    PlaywrightSession session = browserPool.acquire();
    try {
        loginStateManager.loadState(session, getPlatformCode());
        // 1. 打开内容管理页
        session.getPage().navigate(getContentManagementUrl());
        session.getPage().waitForLoadState();
        // 2. 定位目标文章（子类实现）
        locateArticle(session, title, platformUrl);
        // 3. 点击删除（子类实现）
        clickDelete(session);
        // 4. 确认弹窗
        confirmDelete(session);
        // 5. 截图
        String screenshot = session.screenshot();
        return RetractResult.success(getPlatformCode(), screenshot);
    } catch (Exception e) {
        return RetractResult.fail(getPlatformCode(), e.getMessage());
    } finally {
        browserPool.release(session);
    }
}

/** 打开内容管理页 */
protected abstract String getContentManagementUrl();

/** 定位到目标文章 */
protected abstract void locateArticle(PlaywrightSession s, String title, String url);

/** 点击删除按钮 */
protected abstract void clickDelete(PlaywrightSession s);

/** 确认删除弹窗 */
protected void confirmDelete(PlaywrightSession s) {
    // 通用: 等待确认按钮出现并点击
    s.getPage().locator("button:has-text('确定'), button:has-text('确认'), " +
        "button:has-text('删除'), .confirm-btn").first().click();
}
```

| 决策 | 选择 | 理由 |

## 14. 验证方案

1. **视频校验**: 上传100MB视频 → 各平台预览Tab显示不同的校验结果（B站✅、小红书⚠不支持）
2. **视频超大**: 上传2GB视频 → 头条Tab显示⚠超出限制 → 点击压缩到4GB以内
3. **平台管理**: 新增CSDN → 触发登录 → Chrome窗口弹出 → 扫码登录 → 前端显示登录成功 → CSDN Tab出现
4. **删除平台**: 删除小红书 → Tab消失 → cookie文件被清理
5. **模板应用**: 点「种草推荐」→ 预览编辑器显示改写内容（含emoji）→ 用户修改几句话 → 内容保存
6. **预览编辑器**: 在预览中拖拽图片到新的位置 → 切换Tab再切回 → 改动保留
7. **多平台发布**: 勾选3个平台 → 一键发布 → SSE进度更新 → 每个平台取各自版本发布
8. **内容撤回**: 已成功发布的条目 → 点「撤回」→ 后端Playwright打开管理页 → 定位文章 → 删除 → SSE通知撤回成功 → publish_log状态更新为RETRACTED
9. **撤回失败处理**: 模拟撤回失败 → 显示手动处理提示 + 截图留存

# 附录C：数据库SQL文档

```sql
-- =============================================
-- 多平台内容发布工具 - 数据库初始化脚本
-- 数据库: MySQL 8.0+
-- =============================================

CREATE DATABASE IF NOT EXISTS content_publish
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;

USE content_publish;

-- =============================================
-- 1. 内容主表
-- =============================================
CREATE TABLE content (
    id          BIGINT AUTO_INCREMENT PRIMARY KEY,
    title       VARCHAR(255) NOT NULL COMMENT '文章标题',
    tiptap_json LONGTEXT NOT NULL COMMENT 'Tiptap ProseMirror JSON',
    cover_image VARCHAR(500) DEFAULT NULL COMMENT '封面图URL',
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    deleted     TINYINT(1) DEFAULT 0 COMMENT '逻辑删除',
    INDEX idx_created_at (created_at),
    INDEX idx_deleted (deleted)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容主表';

-- =============================================
-- 2. 平台版本表（每个平台独立编辑后的内容）
-- =============================================
CREATE TABLE content_platform_version (
    id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
    content_id          BIGINT NOT NULL COMMENT '内容ID',
    platform_code       VARCHAR(50) NOT NULL COMMENT '平台代码',
    adapted_html        LONGTEXT NOT NULL COMMENT '适配+用户微调后的HTML',
    applied_template_id BIGINT DEFAULT NULL COMMENT '使用的模板ID',
    is_edited           TINYINT(1) DEFAULT 0 COMMENT '用户是否手动微调过',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at          DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_content_platform (content_id, platform_code),
    INDEX idx_content_id (content_id),
    INDEX idx_platform_code (platform_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='内容平台版本表';

-- =============================================
-- 3. 发布记录表
-- =============================================
CREATE TABLE publish_log (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    content_id      BIGINT NOT NULL COMMENT '内容ID',
    platform_code   VARCHAR(50) NOT NULL COMMENT '平台代码',
    status          VARCHAR(30) NOT NULL DEFAULT 'PENDING'
                    COMMENT 'PENDING/PREFLIGHT/FILLING/PUBLISHING/CONFIRMING/SUCCESS/FAILED/RETRACTING/RETRACTED',
    platform_url    VARCHAR(500) DEFAULT NULL COMMENT '发布后文章链接',
    error_msg       VARCHAR(500) DEFAULT NULL COMMENT '错误信息',
    screenshot      MEDIUMTEXT DEFAULT NULL COMMENT '发布后/失败截图(base64)',
    retracted_at    DATETIME DEFAULT NULL COMMENT '撤回时间',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_content_id (content_id),
    INDEX idx_platform_code (platform_code),
    INDEX idx_status (status),
    INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='发布记录表';

-- =============================================
-- 4. 用户平台表
-- =============================================
CREATE TABLE user_platform (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    platform_code   VARCHAR(50) NOT NULL COMMENT '平台代码',
    platform_name   VARCHAR(100) NOT NULL COMMENT '平台显示名',
    login_url       VARCHAR(500) NOT NULL COMMENT '登录页URL',
    editor_url      VARCHAR(500) NOT NULL COMMENT '编辑器URL',
    is_builtin      TINYINT(1) DEFAULT 0 COMMENT '是否系统内置',
    is_active       TINYINT(1) DEFAULT 1 COMMENT '是否启用',
    sort_order      INT DEFAULT 0 COMMENT '排序',
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_platform_code (platform_code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户平台表';

-- =============================================
-- 5. 平台账号表（登录态）
-- =============================================
CREATE TABLE platform_account (
    id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_platform_id    BIGINT NOT NULL COMMENT '关联用户平台',
    cookie_file_path    VARCHAR(500) NOT NULL COMMENT 'cookie持久化文件路径',
    display_name        VARCHAR(100) DEFAULT NULL COMMENT '账号显示名',
    is_active           TINYINT(1) DEFAULT 1 COMMENT '登录态是否有效',
    last_login_at       DATETIME DEFAULT NULL COMMENT '最后登录时间',
    created_at          DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_platform_id (user_platform_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='平台账号表';

-- =============================================
-- 6. AI改写任务表
-- =============================================
CREATE TABLE ai_adapt_task (
    id                      BIGINT AUTO_INCREMENT PRIMARY KEY,
    content_id              BIGINT NOT NULL COMMENT '内容ID',
    target_platform_code    VARCHAR(50) NOT NULL COMMENT '目标平台',
    preset_template         VARCHAR(50) DEFAULT NULL COMMENT '使用的预设模板',
    user_prompt             TEXT DEFAULT NULL COMMENT '用户自定义提示词',
    adapted_content         LONGTEXT DEFAULT NULL COMMENT '改写结果',
    tokens_used             INT DEFAULT 0 COMMENT 'Token消耗',
    created_at              DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_content_id (content_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI改写任务表';

-- =============================================
-- 7. 风格模板表
-- =============================================
CREATE TABLE style_template (
    id                BIGINT AUTO_INCREMENT PRIMARY KEY,
    name              VARCHAR(100) NOT NULL COMMENT '模板名称',
    icon              VARCHAR(10) DEFAULT '📝' COMMENT '图标',
    description       VARCHAR(200) DEFAULT NULL COMMENT '描述',
    reference_type    VARCHAR(10) DEFAULT 'TEXT' COMMENT '参考类型: TEXT/IMAGE',
    reference_sample  TEXT DEFAULT NULL COMMENT '参考文本样本',
    reference_image   VARCHAR(500) DEFAULT NULL COMMENT '参考图片URL',
    system_prompt     TEXT NOT NULL COMMENT 'DeepSeek System Prompt',
    extracted_style   TEXT DEFAULT NULL COMMENT 'AI提取的风格特征(JSON)',
    is_preset         TINYINT(1) DEFAULT 0 COMMENT '系统预置=1, 用户自建=0',
    user_id           BIGINT DEFAULT NULL COMMENT '自建模板关联用户',
    order_no          INT DEFAULT 0 COMMENT '排序',
    use_count         INT DEFAULT 0 COMMENT '使用次数',
    created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at        DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_is_preset (is_preset),
    INDEX idx_user_id (user_id),
    INDEX idx_use_count (use_count)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='风格模板表';

-- =============================================
-- 8. 上传文件表
-- =============================================
CREATE TABLE upload_file (
    id                BIGINT AUTO_INCREMENT PRIMARY KEY,
    original_name     VARCHAR(255) NOT NULL COMMENT '原始文件名',
    stored_path       VARCHAR(500) NOT NULL COMMENT '存储路径',
    file_type         VARCHAR(20) NOT NULL COMMENT 'IMAGE/VIDEO',
    file_size         BIGINT NOT NULL COMMENT '原始字节数',
    compressed_size   BIGINT DEFAULT NULL COMMENT '压缩后字节数',
    width             INT DEFAULT NULL COMMENT '宽度',
    height            INT DEFAULT NULL COMMENT '高度',
    duration          INT DEFAULT NULL COMMENT '视频时长(秒)',
    thumbnail_path    VARCHAR(500) DEFAULT NULL COMMENT '缩略图路径',
    upload_status     VARCHAR(20) DEFAULT 'UPLOADING' COMMENT 'UPLOADING/COMPRESSING/READY',
    created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_file_type (file_type),
    INDEX idx_upload_status (upload_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='上传文件表';
```
